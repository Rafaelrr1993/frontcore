Criador de Cupons

Recriação e geração de cupons NFC-e

O que é

Monta o arquivo de cupom fiscal (texto de largura fixa + XML da NFC-e anexado) que o sistema do PDV grava — sem precisar digitar campo por campo. Roda inteiramente no seu navegador: o XML que você cola e o cupom gerado nunca saem da sua máquina, nada é enviado a nenhum servidor.

Recriar a partir de modelo

Copia um cupom-modelo já existente e correto, trocando só o número do cupom, a chave de acesso e o XML anexado. Uso: reenvio da mesma venda com número novo (ex. depois de "problemas com a rede").

Gerar cupom completo

Monta o cabeçalho do cupom inteiro, campo a campo, só a partir do XML — não precisa de um cupom-modelo.

      Ajuda — Como usar "Recriar a partir de modelo"
      
        
        
      1. Em "1. Cupom-modelo", selecione um arquivo de cupom já existente e correto (geralmente com os mesmos produtos/itens do cupom que você quer recriar — normalmente um reenvio da mesma venda).
        2. 
        
      2. Cole no campo "2. Cole aqui o XML do novo cupom" o XML completo que você pegou no tramitador (Ctrl+C / Ctrl+V).
        3. 
        
      3. Se este cupom estiver substituindo manualmente um registro anterior, escolha "35CANCELAMENTO SUBSTITUICAO" na "Linha especial" (por padrão a página mantém o que já existia no modelo).
        4. 
        
      4. Clique em "Gerar prévia". A página mostra o número/chave antigos e os novos, quantas linhas de item tiveram o número do cupom trocado (deve bater com a quantidade de itens do cupom), avisos — não ignore avisos — e a prévia completa do arquivo final.
        5. 
        
      5. Clique em "Baixar arquivo". Em navegadores baseados em Chromium (Chrome, Edge) abre a caixa "Salvar como" com o nome já sugerido no padrão certo; em outros navegadores, o arquivo vai direto para a pasta Downloads.
        6. 
      
      
      
      Importante: a página assume que o cupom-modelo tem os mesmos itens do cupom que está sendo recriado (mesmo CNPJ, mesmo PDV, mesmos produtos). Se o novo cupom tiver produtos/itens diferentes do modelo, ela avisa que não achou o número antigo nas linhas de item e não gera automaticamente os itens novos — nesse caso a recriação continua manual.

      Ajuda — Como usar "Gerar cupom completo"
      
        
        
      1. Cole no campo o XML completo da NFC-e (o mesmo que se pega no tramitador).
        2. 
        
      2. Marque a "Linha especial" só se este cupom estiver substituindo manualmente um registro anterior (é uma decisão do processo, não vem do XML — por padrão fica "Nenhuma").
        3. 
        
      3. Clique em "Gerar prévia" e confira o resumo e os avisos.
        4. 
        
      4. Se aparecer um aviso pedindo o "Código forma pagto" (acontece quando a página ainda não conhece o código de forma de pagamento cadastrado nesta loja — ele não vem do XML, é um cadastro interno de cada loja), preencha "Código forma pagto" e "Descrição" com o valor certo e clique em "Gerar prévia" de novo. A página memoriza esse código neste navegador — da próxima vez que aparecer essa loja + essa forma de pagamento, ela já usa sozinha, sem precisar digitar de novo. Um código zerado (0000) pode fazer o sistema que recebe o cupom dar erro de "forma de pagamento não vinculada".
        5. 
        
      5. Clique em "Baixar arquivo" — o nome já vem sugerido certo.
        6. 
      
      
      
      
        Sobre a memória de forma de pagamento: ao contrário do programa desktop
        (que grava um arquivo ao lado do .exe, podendo ser copiado de um PC pro
        outro), esta página guarda os códigos aprendidos só no navegador onde você usou —
        cada computador/navegador aprende por conta própria.
      
      
    
      

    
      
      Precisão e limitações conhecidas
      
      Comparando o cupom gerado contra cupons reais completos, campo a campo:
      
      
        
        
      • Registro 51 (chave/PDV) e 00 (cabeçalho da venda): praticamente 100% idênticos ao original (valor total, troco, data/hora, operador, CNPJ da loja — tudo tirado do XML).
        • 
        
      • Registro 02 (itens): ~97% idêntico em pagamento à vista; os campos que não existem em lugar nenhum do XML (departamento/categoria/subcategoria/segmento do cadastro de produtos, "registrador" fiscal por alíquota, contador "CCF do Cupom Fiscal", percentuais de IBPT) usam uma aproximação fixa e sempre geram um aviso.
        • 
        
      • Registro 01 (pagamento): os campos fiscais principais (forma de pagamento, descrição, valor, data) batem certinho. Para cartão/PIX/carteira digital, os dados do terminal (NSU, bandeira, código de autorização) que só existem no sistema de TEF do PDV ficam em branco.
        • 
      
      
      
      Sempre revise a prévia e os avisos antes de usar um cupom gerado — principalmente se a venda usou cartão/TEF ou teve alíquota de ICMS reduzida.
